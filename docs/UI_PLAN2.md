
# Switch-A UI 增强设计计划

## 📋 概述

本计划将后端已支持但 UI 未暴露的功能分为 **4 个阶段**，按优先级和复杂度递进实现。

> 💡 **简化方案**：考虑到 Provider 数量 <20 个，阶段三采用增强现有页面的方式，
> 而非新建独立 Health 页面，降低复杂度并避免功能重复。

| 阶段 | 目标 | 复杂度 |
|------|------|--------|
| 一 | Provider 健康信息增强 | ⭐⭐ | ✅ Completed |
| 二 | 配置页面补全 | ⭐⭐ |
| 三 | Dashboard 健康概览增强 | ⭐⭐ |
| 四 | 详情抽屉与交互优化 | ⭐⭐⭐ |

## 🚀 阶段一：Provider 健康信息增强（基础改进） ✅ Completed

**目标**：在现有 Providers 页面补充关键的健康状态详情

### 1.1 Provider 表格增强

在 Providers 列表表格中，为每行添加以下信息展示：

| 新增列/信息 | 展示方式 | 说明 |
|------------|---------|------|
| **失败次数** | 数字徽章 | `fail_count`，红色数字，0 时可隐藏 |
| **熔断恢复时间** | 倒计时/时间戳 | `disabled_until`，仅熔断时显示 |
| **熔断原因** | Tooltip 或小字 | `disabled_reason`，悬停/点击查看 |
| **最后错误** | Tooltip | `last_error`，鼠标悬停显示完整错误 |

### 1.2 Provider 操作按钮

在每行操作列添加：

- **🔄 重置按钮**：调用 `POST /admin/api/providers/{id}/reset`
  - 仅当状态为 `unhealthy` 时可点击
  - 点击后弹出确认对话框："确定要重置该 Provider 的熔断状态吗？"
  - 成功后刷新列表

### 1.3 状态徽章增强

当前只有颜色区分，建议增加：
- Unhealthy 状态旁显示小图标（如⚠️）
- 悬停时显示详细原因 tooltip

### 1.4 熔断恢复时间的特殊处理

> ⚠️ **已知问题**：熔断恢复是"懒触发"的，只有新请求到来时才会调用 `RecoverIfExpired`。
> 如果 `disabled_until` 已过期但无新请求，数据库中 `available` 仍为 `false`，
> 前端会显示"熔断中"，但实际上 Provider 已可被使用。

**UI 处理方案（三选一）：**

| 方案 | 实现方式 | 优点 | 缺点 |
|-----|---------|-----|------|
| **A. 前端智能判断** | 前端比较 `disabled_until` 与当前时间，若已过期则显示"待恢复" | 无需后端改动，状态更准确 | 前后端状态理解不一致 |
| **B. 显示倒计时** | 熔断时显示倒计时，归零后自动变为"待恢复"或"可用(待验证)" | 用户体验直观 | 仍需前端逻辑判断 |

**推荐方案 A + B 组合：**

```
状态显示逻辑：
if (enabled == false) → ⚪ 已禁用 (用户禁用)
if (available == false && enabled == true && disabled_until > now) → 🔴 熔断中
if (available == false && enabled == true && disabled_until <= now) → 🟡 待恢复
if (available == true && enabled == true) → 🟢 Healthy
```

## 🛠️ 阶段二：配置页面补全（功能完善）

**目标**：将后端支持的所有配置项暴露到配置页面

### 2.1 新增配置分组

在 Config 页面添加新的配置区块：

#### 「超时设置」分组
| 配置项 | 表单类型 | 说明 |
|-------|---------|------|
| `upstream_connect_timeout` | 数字输入框 + 单位选择 | 上游连接超时 |
| `first_byte_timeout` | 数字输入框 + 单位选择 | 首字节超时 |
| `upstream_read_timeout` | 数字输入框 + 单位选择 | 读取超时 |
| `sse_idle_timeout` | 数字输入框 + 单位选择 | SSE 空闲超时 |

#### 「请求限制」分组
| 配置项 | 表单类型 | 说明 |
|-------|---------|------|
| `max_body_size` | 数字输入框 + 单位(KB/MB) | 最大请求体大小 |
| `max_retries` | 数字输入框 (0-10) | 最大重试次数 |

#### 「其他设置」分组
| 配置项 | 表单类型 | 说明 |
|-------|---------|------|
| `trust_proxy_headers` | 开关 Switch | 是否信任代理头 |
| `log_retention_days` | 数字输入框 | 日志保留天数 |

### 2.2 表单交互设计

- 每个分组可折叠/展开
- 添加配置说明/帮助图标（?），悬停显示配置用途
- 修改后显示"未保存"提示
- 保存时校验数值范围合理性

## 📊 阶段三：Dashboard 健康概览增强（简化方案）

> 💡 **设计决策**：Provider 数量 <20 个，无需独立 Health 页面，改为增强 Dashboard 和 Providers 页面。

**目标**：在现有页面基础上增强健康监控能力

### 3.1 健康状态统计卡片

在 Dashboard 顶部添加醒目的健康状态统计卡片：

```
┌─ Health Overview ───────────────────────────────────────┐
│  ┌───────────┐  ┌───────────┐  ┌───────────┐           │
│  │  🟢 12    │  │  🔴 2     │  │  ⚪ 1     │           │
│  │  Healthy  │  │ Unhealthy │  │ Disabled  │           │
│  │   [>]     │  │   [>]     │  │   [>]     │  ← 可点击 │
│  └───────────┘  └───────────┘  └───────────┘           │
└─────────────────────────────────────────────────────────┘
```

**卡片设计要点：**
- 三个卡片分别统计 Healthy / Unhealthy / Disabled 数量
- 点击卡片跳转 Providers 页并自动筛选对应状态
- Unhealthy 卡片使用警示色背景（如浅红色）
- 卡片下方可显示简要摘要（如 "2 circuit breaker, 1 timeout"）

### 3.2 Provider Status 区块增强

在 Dashboard 的 Provider Status 区块增加健康详情和自动刷新：

```
┌─────────────────────────────────────────────────────────┐
│  Provider Status              [🔄 自动刷新: 10s ▾]     │
├─────────────────────────────────────────────────────────┤
│  ┌───────────────────────────────────────────────────┐  │
│  │ openai-1    🟢 Healthy     98% ▏ 1,234 req        │  │
│  ├───────────────────────────────────────────────────┤  │
│  │ openai-2    🔴 熔断中      ⏱️ 2:30 恢复           │  │
│  │             └─ 失败 5 次 · connection timeout     │  │  ← 新增：异常详情行
│  ├───────────────────────────────────────────────────┤  │
│  │ claude-1    ⚪ 已禁用      —                      │  │
│  └───────────────────────────────────────────────────┘  │
│                                                         │
│  [🔄 批量重置异常] ← 当有异常 Provider 时显示           │
└─────────────────────────────────────────────────────────┘
```

**增强要点：**
- **自动刷新**：支持 5s / 10s / 30s / 关闭 四档选择，默认 10s
- 异常 Provider 展开显示：失败次数、恢复倒计时、最后错误
- 点击异常 Provider 可直接跳转 Providers 页并聚焦该项
- 添加「批量重置」按钮（调用已有的批量 API）

### 3.3 Providers 页面状态筛选增强

利用现有 `statusFilter`，增加更细粒度的筛选选项：

| 原筛选值 | 新增筛选值 | 说明 |
|---------|-----------|------|
| `healthy` | — | 保持不变 |
| `unhealthy` | `circuit-open` | 熔断中（倒计时未结束） |
| — | `pending-recovery` | 待恢复（倒计时已结束） |
| `disabled` | — | 保持不变（用户禁用） |

### 3.4 Providers 页面自动刷新

为 Providers 列表页也添加自动刷新功能：
- 右上角添加刷新控件，与 Dashboard 保持一致
- 支持 5s / 10s / 30s / 关闭 四档选择
- 刷新时保持当前筛选和排序状态

## 📝 阶段四：详情页与高级功能（体验优化）

**目标**：添加 Provider/Group 详情抽屉，提升整体体验

### 4.1 Provider 详情抽屉（Drawer）

> 使用侧边抽屉而非独立页面，保持上下文连贯性。

点击 Provider 名称或「查看详情」按钮，从右侧滑出抽屉：

```
┌─────────────────────────────────────────────────────┐
│  Provider: openai-main                      [✕]    │
├─────────────────────────────────────────────────────┤
│  基本信息                                           │
│  ├─ ID: provider_123                                │
│  ├─ Endpoint: https://api.openai.com/v1             │
│  ├─ Group: default                                  │
│  └─ Priority: 1 · Weight: 1                         │
├─────────────────────────────────────────────────────┤
│  健康状态                                           │
│  ├─ 当前状态: 🔴 熔断中                              │
│  ├─ 失败次数: 5                                     │
│  ├─ 熔断原因: auto: circuit breaker triggered       │
│  ├─ 恢复时间: 2:30 后自动恢复                        │
│  └─ 最后错误: connection timeout                    │
│                                    [🔄 重置状态]    │
├─────────────────────────────────────────────────────┤
│  最近请求                            [查看全部 →]   │
│  ├─ ✅ gpt-4 · 234ms · 10:30:15                     │
│  ├─ ❌ gpt-4 · timeout · 10:29:45                   │
│  └─ ❌ gpt-4 · 429 · 10:29:30                       │
├─────────────────────────────────────────────────────┤
│  [✏️ 编辑] [⏸️ 禁用] [🗑️ 删除]                      │
└─────────────────────────────────────────────────────┘
```

**功能要点：**
- 整合基本信息 + 健康状态 + 操作按钮
- 最近请求：复用 Logs API（`provider_id` 筛选），显示最近 5 条
- 「查看全部」跳转 Logs 页并自动筛选该 Provider

### 4.2 Group 详情抽屉

类似结构，展示：
- Group 基本信息（策略、权重、优先级）
- 下属 Provider 列表（带状态指示器）
- 健康 Provider 占比进度条

### 4.3 交互优化

- Provider/Group 名称可点击，触发详情抽屉
- 抽屉内操作（编辑/删除）成功后自动关闭并刷新列表
- 支持 ESC 键关闭抽屉
